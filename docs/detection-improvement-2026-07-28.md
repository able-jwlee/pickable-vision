## 1. 결론 요약

| 경로 | 검출 수 | 정밀도 | 재현율 | 무작위 산포 기대 재현율 |
|---|---|---|---|---|

2~4차는 서로 맞물렸다. 둥글기 게이트가 모양 판정을 경계 거칠기에 둔감하게 만든
덕에, 그 전에는 정밀도를 무너뜨렸던 적극적인 watershed(1.2배)가 안전해졌다 —
같은 설정이 둥글기 도입 전 87.8%/55.7% 에서 **91.4%/57.6%** 로 양쪽 다 좋아졌다.

세 번 모두 **계측으로 주범을 특정한 뒤** 나왔다. 감도를 올려 교환하는 방식이
아니라 잘못된 판정을 고친 것이라 정밀도와 재현율이 같이 올랐다.

기존 경로는 네 그룹 **모두에서 무작위 산포보다 나빴다.** 같은 개수(73,402개)의
점을 접시에 무작위로 뿌리면 확률적으로 1,070개를 맞히는데 실제로는 622개만
맞혔다 — 검출기가 콜로니를 체계적으로 **피하고** 있었다는 뜻이고, 원인은 극성
가정이 반대였기 때문이다.

검출 수가 73,402 → 1,462로 줄어든 것도 중요하다. 기존 경로는 이미지당 평균
1,800개를 뱉었는데 정답은 평균 48개다. 로봇 입장에서 그중 무엇을 집어도
99% 확률로 빈 한천이었다.

### 권장 운용법 (2026-08-03 갱신)

**아무것도 지정하지 말 것.** 기본값이 실측 최적이다. 접시 극성까지 서버가
자동 판정하므로(§8.4e, 정확도 43/43) 오퍼레이터 입력으로 얻을 이득이 없다.

이전 버전의 이 절은 "콜로니 색을 눈으로 보고 지정하라"고 안내했다. 그때는
`polarity=auto` 가 양극성 병합을 뜻해서 수동 지정이 정밀도를 5%p 올렸기
때문이다. 이제 `auto` 가 접시별 판정을 뜻하므로 **그 안내는 무효다.**

조절이 필요한 경우는 두 가지뿐이다:

| 상황 | 무엇 | 결과 |
|---|---|---|
| 놓치는 것이 빈 웰보다 훨씬 아깝다 | `sensitivity` ~60 | 정밀도 81% / 재현율 72% |
| 오검출 비용이 크다 (시퀀싱까지 가는 워크플로) | `sensitivity` 42 | 정밀도 93% / 재현율 64% |

재현율 약 74.0%** — "재현율 68.5%"는 알고리즘이 전반적으로 약한 것이 아니라
**특정 촬영 조건에서 약한** 것이다.

## 2. 기존 경로가 실패한 근본 원인

`threshold_offset` 같은 감도 knob 튜닝으로는 고칠 수 없는 문제였다. 틀린 것은
파라미터 값이 아니라 `app/detector.py`가 가정하는 **이미지 모델 자체**였다.

### 2.1 극성 — 전역 고정이 원리적으로 불가능

`DEFAULT_INVERT=True`(black-hat)는 어두운 콜로니를 가정한다. 콜로니 내부와
**주변 한천만** 국소 비교한 실측값:

| 그룹 | 국소 대비 중앙값 | 밝은 콜로니 비율 |
|---|---|---|
| lower-resolution | **+38.4** | 100% |
| higher-res/bright | **−36.7** | 2% |
| higher-res/dark | **−38.4** | 6% |
| higher-res/vague | −2.8 | 28% (혼재) |

데이터셋마다 극성이 반대이고, `vague`는 한 장 안에서도 섞여 있다.
→ **양극성을 모두 검출한 뒤 blob마다 판정**하는 구조로 해결.

### 2.2 스케일 — 커널이 콜로니보다 5~13배 작다

`tophat_kernel=31`인데 콜로니 지름은 중앙값 57px, 최대 404px이다. 커널이 콜로니보다
작으면 top-hat이 큰 콜로니 내부에서 응답 0이 되고 테두리만 남아, watershed가
이미지당 2,000~3,000개 파편을 만든다.

결정적 증거: `max_area`를 5,000에서 200,000으로 올려도 **검출 수가 전혀 변하지
않았다.** 큰 blob이 애초에 생성되지 않기 때문이다.

→ **스케일 정규화 LoG의 scale-space 국소최대**로 콜로니 크기를 스스로 추정하도록 해결.

### 2.3 ROI — 플레이트 기하구조 불일치

`_well_mask()`의 2×4 격자는 8웰 몰딩 플레이트 가정인데 `sample/`은 원형 petri
접시다. 격자를 끄기만 해도 재현율이 23.8% → 57.9%로 올랐다.

→ **HoughCircles로 접시 원을 직접 검출**(밝기 극성 무관)해 해결.

## 3. "콜로니처럼 생긴 것만" 판정하는 축

요청받은 글씨·벽·평면 배제는 서로 독립인 네 축의 조합으로 해결했다.

| 축 | 콜로니 | 글씨·벽·평면 | 성격 |
|---|---|---|---|
| **t-통계량** (면적 가중 Welch t) | 높음 | 균일 평면은 0 근처 | 스케일·극성 무관 |
| **\|Δ채도\|** (내부 − 주변) | 7~57 | −0.1~+1.7 | 데이터셋 무관 |
| **원형도·solidity·종횡비** | 둥글고 채워짐 | 획 글씨·벽 주름 탈락 | 모양 |
| **원형 ROI 수축** | 접시 내부 | 테두리 링·메니스커스 배제 | 위치 |

### 3.1 절대 대비가 아니라 t-통계량이어야 하는 이유

`vague` 그룹의 큰 콜로니는 대비가 256단계 중 **2~3단계**뿐인데 지름이 200px다.
절대 대비로는 노이즈와 구분되지 않지만, 평균의 표준오차는 `std/√N`이므로 넓은
영역에서는 작은 대비도 통계적으로 유의해진다. 이 하나의 척도가 네 그룹에
스케일 무관하게 적용된다.

### 3.2 점자식 인쇄 글씨는 모양으로 못 걸러낸다

FP를 시각화해 확인한 결과 주된 오검출원은 **점자식(dot-matrix) 인쇄**였다.
개별 점이 실제로 완벽하게 둥글어서 원형도 게이트를 그대로 통과한다.
분리 축은 색이었다 — 콜로니는 색소가 있고 잉크는 무채색이다.

단, **절대 채도는 쓸 수 없다.** 잉크와 콜로니의 절대 채도가 데이터셋마다
겹친다(lower-res 82 대 121, dark 22 대 111). 주변 대비 **상대 채도**를 써야 하고,
**반드시 절댓값**이어야 한다 — 콜로니가 한천보다 채도가 낮은 접시도 있다.

## 4.5 `/detect` 조절 파라미터

이미지마다 밝기와 콜로니 크기가 다르므로, **조절이 필요한 것만** 요청 필드로
노출했다. 밝기·콜로니 극성(밝은지 어두운지)·접시 위치와 크기는 알고리즘이
자동 처리하므로 knob이 없다 — 그게 이번 개선의 핵심이었다.

| 필드 | 범위 | 기본값 | 의미 |
|---|---|---|---|
| `polarity` | `auto`/`both`/`bright`/`dark` | `auto` | `auto` = **접시별 자동 판정**(정확도 43/43, §8.4e). `both` = 구동작(양극성 병합). 수동 지정은 자동이 틀릴 때만 |
| `min_t` | 1 ~ 200 | **25** | 감도. 낮추면 흐린 콜로니까지 잡고 오검출↑ (35 → 25 로 하향, §8.4f) |
| `min_solidity` | 0 ~ 1 | **0.75** | 면적 ÷ convex hull. 0.90 에서 내려 곡선 전체가 올랐다 (§8.4d) |
| `watershed_split` | bool | **true** | 붙은 콜로니를 거리변환 watershed 로 분리 |
| `min_roundness` | 0 ~ 1 | **0.55** | 면적 ÷ 최소외접원 면적 — 주된 모양 판정. **완화 비권장**(§8.4g) |
| `sensitivity` | 0 ~ 100 | — | 위를 추상화한 슬라이더 (50 → `min_t` 25 = 서버 기본값) |
| `min_diam_frac` | 0 ~ 1 | **0** (제한 없음) | 콜로니 지름 ÷ 접시 지름 하한 |
| `max_diam_frac` | 0 ~ 1 | **0** (제한 없음) | 같은 기준 상한 |
| `colour_credit` | 1 ~ 8 | **1.0** (끔) | 색이 뚜렷하면 감도 요구치를 이 배율까지 할인 |
| `work_size` | 384 ~ 2048 | **1280** | 처리 해상도(최대변 px). 1024 에서 올려 곡선 전체가 +1.2~1.6%p (§8.4h) |
| `adaptive_scale` | bool | **false** | 해상도 자동 조정 (실측에서 나빠 기본 끔) |
| `pick_radius_min` | ≥ 0 | **0** (제한 없음) | 피킹 후보 반지름 하한 (원본 px) |
| `pick_radius_max` | ≥ 0 | **0** (제한 없음) | 상한 |
| `plate_type` | `petri` / `well8` | `petri` | 플레이트 기하구조 |
| `method` | `blob` / `tophat` | `blob` | 검출 경로 |
| `marker` | `square` / `circle` | `square` | 응답 이미지 표시 모양. 콜로니가 원형이라 네모가 더 잘 보인다 |
| `min_roundness` / `min_solidity` | 0 ~ 1 | 0.55 / **0.75** | 모양 게이트 (§8.4d) |

모든 값은 응답의 `applied_params`로 되반환되어 재현·이슈 리포트에 쓸 수 있다.

### 크기를 "비율"로 받는 이유

콜로니 크기를 작업 픽셀이나 원본 픽셀로 받으면 해상도·카메라·촬영 거리마다
같은 숫자가 다른 물리 크기를 뜻해 오퍼레이터가 쓸 수 없다. **접시 지름 대비
비율**로 두면 petri 접시가 물리적 규격품이므로 항상 같은 물리 크기가 된다.
실측 분포(정답 1,886개): 콜로니 지름은 접시 지름의 약 1.2%~45%, 중앙값 약 7%.

기본값을 "제한 없음"으로 둔 이유는 이 분포가 워낙 넓어 어떤 고정 창도 진짜
콜로니를 버리기 때문이다. 크기 제한은 "이 접시에선 큰 것만 집어라" 같은
**사용자 의도**를 표현할 때만 켜는 knob이다 — 알고리즘이 추측할 수 없는 것.

### 피킹 판정 — 기본적으로 끈다 (검출된 것 = 피킹 대상)

원래 `scoring.py`는 검출된 콜로니 중 "로봇이 안전하게 단일 클론을 집을 수 있는
것"만 `pickable=true`로 표시했다. 기준은 이웃 최소 거리·크기 대역·원형도·테두리
여백이었고, 목적은 정당하다 — 붙은 콜로니를 집으면 두 균주가 섞인 혼합 클론이
되고 그건 며칠 뒤 시퀀싱 단계에서야 드러난다.

**그러나 실측상 그 구분은 작동하지 않았다.** 검출 1,333개 중 1,286개(96.5%)가
통과했고, 탈락 47개도 대부분 테두리(40개)였다. 원형도는 검출 게이트(0.70)가
피킹 게이트(0.55)보다 이미 엄격해서 **논리적으로 0개** 탈락이었다.

원인은 기준값이 **원본 픽셀 단위**이고 8웰 플레이트(1350×910)에 맞춰 튜닝된
것이라는 데 있다. 4000px 페트리 이미지에서 이웃 최소 거리 20px은 콜로니 지름이
100~400px인 것에 비해 무의미하고, 테두리 여백 60px은 얇은 링일 뿐이다.
반대로 크기 상한 20px은 너무 엄격해서 페트리 접시의 피킹 대상을 **전부** 없앴다
(`13895.jpg`: 검출 15개 / 피킹 0개).

구분이 있는 척하면서 실제로는 없었으므로 **껐다**. 기준은 `score_colonies()`
인자로 남아 있어 요청별로 켤 수 있고, `score`와 `pick_top_n`(예: 96핀)은 그대로
동작하므로 **랭킹은 유지된다** — 고립되고 둥근 콜로니가 먼저 선택된다.

다시 켤 때는 **원본 픽셀이 아니라 접시 지름 대비 비율로 재설계해야 한다.**
그러지 않으면 카메라·해상도가 바뀔 때 조용히 무력화된다 — 지금이 그 사례다.

**이 선택의 대가:** 오검출 하나가 곧 로봇이 빈 한천을 찍는 것이 된다. 그래서
정밀도가 전보다 더 중요해졌고, 기본 감도를 50(정밀도 90%)에서 올리지 않는 편이
좋다. 감도를 75로 올리면 재현율 +3%p를 얻는 대신 100개당 빈 웰이 10개에서
22개로 늘어난다.

## 4.6 오퍼레이터 UI 연결

`docs/mockup/operator-ui.html` 이 실제 서버에 붙는다. 이미지 선택 또는 업로드 →
검출 → 서버가 표시한 이미지와 콜로니 개수를 보여준다.

**좌표와 이미지를 한 응답에.** `/detect` 는 좌표만, `/detect/preview` 는 이미지만
주므로 둘을 같이 받을 방법이 없었다. `return_image: true` 가 그 간극을 메운다 —
응답의 `annotated_image`(base64)와 `colonies`(좌표)가 함께 온다.

좌표는 **항상 원본 픽셀** 기준이고 이미지는 전송을 위해 축소될 수 있다
(기본 JPEG·최대폭 1600 — 2048px 접시에서 PNG 원본 4.2MB 대 JPEG 279KB).
축소 이미지 위에 좌표를 겹치려면 응답의 `annotated_image_scale` 을 곱한다.

**프리셋.** 촬영 조건별 최적값이 실측상 다르므로 단일 기본값으로는 최적이 안 된다.

| 프리셋 | 설정 | 근거 (실측 F1) |
|---|---|---|
| 기본 (권장) | — | 정밀도 91% / 재현율 58% |
| 작은 콜로니가 많음 | `work_size=1536` | 다른 조건에서는 정밀도 손실이 크다 |
| 흐려서 잘 안 보임 | `colour_credit=1.5` | 흐린 조건 재현율 18.9 → 30.9%, 전체 정밀도 91 → 77% |
| 오검출 줄이기 | `sensitivity=30` | 정밀도 96% / 재현율 44% |

**UI 기본값은 서버 기본값과 일치시켜야 한다.** 어긋나면 UI가 매번 덮어써서 조용히
필터가 켜진다 — 실제로 `pick_radius_max` 에서 겪었다. UI 슬라이더가 20으로 남아
있어서 서버 기본값 0(제한 없음)을 덮어쓰고 피킹 대상이 매번 0이 됐다.

## 8. 남은 과제

### 8.1 병목은 검출이 아니라 판정이다

| 단계 | 정답 1,886개 중 |
|---|---|
| LoG 후보로 잡힘 | **1,838개 (97.5%)** |
| 게이트 생존 | 1,047개 (55.5%) |
| 후보 단계 손실 | 48개 (2.5%) |
| **게이트 손실** | **791개 (41.9%)** |

검출기는 콜로니의 **97.5%를 이미 보고 있다.** 즉 이론적 재현율 상한이 97.5%이고,
현재 57.6%와의 격차 40%p는 전부 판정 문제다. 정보는 이미 이미지에서 추출됐고
버리기만 하고 있다는 뜻이므로, 개선 여지가 크다.

### 8.2 최대 레버는 `bright` 그룹

정답 863개(전체의 46%) 중 431개를 놓친다. 구조적 원인이 있다: 그 그룹 콜로니는
지름 중앙값 40px인데 3,775px 이미지를 1,024로 줄이면 반지름 5px, 내부 픽셀이
30여 개가 된다. t-통계량은 면적 가중이라 픽셀이 적으면 원리적으로 작아진다.
해상도를 올리는 방식은 기각됐으므로(§6) 다른 접근이 필요하다.

### 8.3 `vague` 그룹은 물리적 한계

국소 대비 중앙값이 −2.8, 즉 256단계 중 **3단계**다. 정밀도 76%를 유지하면 재현율
15.8%가 상한이고, t를 낮추면 재현율 63.6%까지 가지만 정밀도가 50%로 무너진다.
이건 알고리즘이 아니라 **촬영 조건(조명·대비) 개선이 훨씬 효과적인 영역**이다.

### 8.4 8웰 플레이트에 라벨이 필요하다

`tests/fixtures/agar_sample.jpg`는 이 프로젝트 하드웨어인 4×2 몰딩 8웰
플레이트다. **정답 라벨이 없어 검출률을 측정할 수 없고, 따라서 튜닝도 검증도
불가능하다.** 그 픽스처에서 blob 경로는 petri용 기본값으로 44개만 찾는데
(t=8에서는 206개), 어느 쪽이 맞는지 판정할 근거가 없다.

**8웰 플레이트 이미지 10~20장에 `sample/`과 같은 형식으로 라벨을 주면**
같은 방법으로 측정·튜닝해서 기본 경로로 전환할 수 있다.
`scripts/evaluate_labeled.py`가 그대로 읽는다.

### 8.4b 이후 채택된 개선 (2026-07-29)

계측을 다시 돌려 주범을 특정하면서 세 번 더 개선했다. 모두 **정밀도를 지키면서**
재현율이 올랐다 — 감도를 낮춰 교환하는 방식이 아니었다.

| 채택 | 근거 | 결과 |
|---|---|---|
| **watershed 분리** (`BLOB_WATERSHED_SPLIT`) | 밀집 접시에서 감도를 50→75로 올려도 검출이 248→252로 거의 안 변했다 — 대비 문제가 아니라 **분할** 문제 | 51.9 → 53.9% 재현율, 정밀도 유지, **네 그룹 전부 개선** |
| **면적 기반 둥글기** (`BLOB_MIN_ROUNDNESS=0.55`) | 한 이미지의 놓친 15개 중 10개(67%)가 둘레 기반 원형도 탈락. 그 지표는 경계 거칠기에 극도로 민감해 방사형 균사를 가진 콜로니를 버린다 | 정밀도 90.0 → **92.9%**, 재현율 53.9 → **55.4%** (동시 개선) |
| **watershed 적극화** (`BLOB_SPLIT_AREA_RATIO` 2.0 → 1.2) | 둥글기가 모양을 지켜주게 되어 안전해졌다 | 재현율 55.4 → **57.6%**, 정밀도 91.4% |

세 번째가 핵심이다. **같은 1.2배 설정이 둥글기 도입 전에는 87.8%/55.7%였는데
도입 후 91.4%/57.6%가 됐다** — 정밀도와 재현율이 함께 3.6%p / 1.9%p 올랐다.
게이트 하나를 올바른 지표로 바꾸자 이전에 불가능했던 축이 열린 것이다.

**추가로 기각된 것:**

| 기각 | 결과 |
|---|---|
| 둘레 기반 원형도 완화·제거 | **무력.** 0.50 → 0.00 까지 결과가 완전히 동일(91.4%/57.7%). 귀속 계측이 지목한 174개는 같은 콜로니의 중복 후보였고 실제 손실이 아니었다. 귀속 계측을 두 번째로 과대해석한 사례 |
| 색 보정 재시도 | **여전히 교환.** 1.5배에서 재현율 57.6→63.8%인데 정밀도 91.4→76.5%. `vague`(18.9→30.9%)와 `bright`에는 유효하므로 **프리셋으로만** 유지 |
| Cellpose 4.x (Cellpose-SAM, 사전학습, CPU) | **CPU 운용 불가.** 정확히 측정한 이미지당 처리 시간(모델 로드 6.1초 별도): **384px 399초 · 512px 1,123초 · 768px 1,829초**. blob 경로는 1.4초다 — **285~1,300배** 느리다. GPU 면 10~20배 빨라져 운용 가능 범위(10~20초)에 들어오지만, **품질 이득은 아직 미검증**이므로 하드웨어를 먼저 사는 것은 순서가 뒤바뀐 것이다. 품질 측정에는 GPU 가 필요 없다 — 느리더라도 CPU 로 먼저 재야 한다. [`scripts/learned/eval_cellpose.py`](../scripts/learned/eval_cellpose.py) |

### 8.4c 극성 지정 — 오늘 가장 큰 이득 (2026-07-29)

알고리즘은 양극성을 모두 검출한 뒤 NMS 로 병합한다. 극성을 노출하면 검출이
늘지 않고 제한만 되므로 재현율이 떨어질 것으로 예상했다. **틀렸다.**

**틀린 극성 분기는 기여 없이 오검출만 추가하고 있었다.** 맞는 극성으로 고정하면
모든 그룹에서 정밀도가 오른다:

| 그룹 | 실측 극성 | 양극성 | 극성 고정 |
|---|---|---|---|
| lower-resolution | 밝은 (100%) | 92.7% | **97.9%** (+5.2%p) |
| higher-res/dark | 어두운 (94%) | 90.3% | **95.2%** (+4.9%p) |
| higher-res/bright | 어두운 (98%) | 93.6% | **95.0%** (+1.4%p) |
| higher-res/vague | 어두운 (72%) | 75.9% | **84.5%** (+8.6%p) |

재현율 손실은 0.6%p 뿐이다. 확보한 정밀도를 감도로 바꾸면:

| 설정 | 정밀도 | 재현율 | F1 |
|---|---|---|---|
| 양극성 · 감도 50 (API 기본값) | 91.4% | 57.6% | 70.7 |
| 극성고정 · 감도 50 | **95.1%** | 57.0% | 71.3 |
| 극성고정 · 감도 60 | **93.3%** | **59.3%** | 72.5 |
| **극성고정 · 감도 70** | **89.9%** | **61.9%** | **73.3** |
| 극성고정 · 감도 80 | 85.0% | 64.2% | 73.1 |

**감도 60은 현재 기본값보다 양쪽이 다 좋다** (정밀도 +1.9%p, 재현율 +1.7%p).
감도 70이면 재현율 61.9%에 정밀도 89.9%다. 그룹별로 `vague` 18.9 → **29.0%**,
`bright` 57.5 → **62.1%** 로 오른다.

**왜 기본값을 고정 극성으로 바꾸지 않는가:** 극성이 데이터셋마다 반대다
(lower-res 는 밝은 콜로니, 나머지는 어두운 콜로니). 전역 기본값으로 고정하면
절반이 무너진다. `auto` 는 사람 입력 없이 안전하게 동작하는 값이고,
**오퍼레이터가 눈으로 판단해 지정하면 그만큼 이득을 얻는** 구조다.

권장 운용 순서: **콜로니 색 지정 → 감도 60~70**.

### 8.4d solidity 게이트가 잘못 조여져 있었다 (2026-08-03)

재현율을 목표로 병목을 다시 계측해 `BLOB_MIN_SOLIDITY` 를 **0.90 → 0.75** 로
내렸다. §8.5 가 "모든 축이 교환일 뿐"이라고 결론했지만 이 축은 예외였다 —
**Pareto 곡선 자체가 올라갔다.**

같은 정밀도에서 재현율을 비교한 실측(39장):

| 정밀도 | 이전 곡선 | solidity 0.75 | 차이 |
|---|---|---|---|
| ~88% | 58.8% | **60.3%** | +1.5%p |
| ~80% | 62.9% | **64.4%** | +1.5%p |
| ~72% | 65.2% | **67.3%** | +2.1%p |
| ~61% | 68.1% | **70.5%** | +2.4%p |

기본 운영점은 91.4%/57.6% → **88.6%/60.3%**, F1 70.7 → 71.7 이고 네 그룹 전부
올랐다(bright 57.5→60.7, dark 75.5→77.7, lower 74.9→77.0, vague 18.9→21.1).
0.75 아래로는 결과가 완전히 동일해 그 값이 포함점이다.

한 지점이 아니라 **모든 운영점에서 위**라는 것이 근거다. 한 지점만 좋아지면
그건 교환을 다르게 표현한 것일 뿐이다.

**재현율 사다리** (solidity 0.75 기준, 감도 슬라이더로 도달 가능):

| 감도 | min_t | 정밀도 | 재현율 | vague |
|---|---|---|---|---|
| 50 (기본) | 35 | 88.6% | 60.3% | 21% |
| ~72 | 25 | 75.6% | 66.4% | 33% |
| ~82 | 20 | 65.3% | 69.0% | 41% |
| ~93 | 15 | 53.7% | 72.9% | 52% |
| 100 | 12 | 46.0% | **75.5%** | **61%** |

재현율 75.5% 가 도달 가능하다는 것이 처음 확인됐다. 대가는 정밀도 46% 다.

**이번 반복에서 추가로 기각된 것:**

| 기각 | 결과 |
|---|---|
| 접시 ROI 수축을 풀면 테두리 콜로니를 회수한다 | **기각.** 정답 54개(2.9%)가 ROI 밖으로 잘리고 전부 중심거리/반지름 0.98~1.12 구간(테두리 부근)임을 확인했는데, `BLOB_DISH_SHRINK` 를 0.98→1.12 로 풀어도 재현율은 57.6→58.0% 에 그쳤다. 들여보낸 후보가 게이트에서 똑같이 죽는다 — ROI 는 병목이 아니었다 |
| 둥글기 게이트를 완화하면 재현율이 오른다 | **기각(재확인).** 둥글기 0.35 + solidity 0.75 는 55.8%/70.3% 인데, 둥글기를 그대로 두고 min_t 만 15 로 내리면 53.7%/**72.9%** 다. 같은 정밀도에서 감도가 더 많이 맞히므로 둥글기를 푸는 것은 손해다 |
| LoG 후보 생성이 병목이다 (OpenCFU score-map 이식 검토) | **기각.** 971.jpg 단계별 계측: 원시 LoG 후보가 정답의 **93.1%** 를 덮는다. 못 잡는 9개도 크기 하한(`r_min`) 때문이 아니다(0/9). NMS 도 무죄다(커버리지 107→106). 손실은 후보 생성이 아니라 그 뒤 게이트에 집중돼 있으므로 후보 생성기를 교체할 이유가 없다 |

**계측 방법 주의:** 모양 게이트들은 `colony_gate()` 의 **함수 기본 인자**라
기본값이 import 시점에 바인딩된다. `config` 를 런타임에 바꿔도 반영되지 않으므로
스윕은 `detect_blobs()` 에 kwargs 로 직접 넘겨야 한다. (`BLOB_DISH_SHRINK` 는
함수 본문에서 읽으므로 런타임 변경이 통한다 — 축마다 다르다.)

### 8.4e 접시별 극성 자동 판정 — 오늘 가장 큰 이득 (2026-08-03)

§8.4c 는 "틀린 극성 분기가 기여 없이 오검출만 추가한다"를 밝히고도 **전역 고정이
불가능하다**는 이유로 오퍼레이터 입력에 맡겼다. 그것이 잘못된 결론이었다 —
전역이 아니라 **접시별**로 판정하면 된다.

**판정 방법: 픽셀 편차 질량.** ROI 안에서 중앙값을 한천으로 보고, 그보다 밝은
픽셀들의 편차 총량과 어두운 픽셀들의 편차 총량을 비교한다. 콜로니는 소수라도
편차 총량으로는 드러난다. 후보를 쓰지 않아 비용이 사실상 0이다.

**정확도 43/43** (실제 39장 + 합성 4종). 점수 분포가 깨끗하게 갈린다 —
어두운 콜로니 접시 −0.51~−0.63, 밝은 콜로니 접시 +0.17~+0.48, 합성 ±1.0.

**효과 (같은 감도에서):** 정밀도 88.6 → **93.8%**, 재현율 −0.8%p.
같은 정밀도에서 재현율을 비교하면 모든 운영점에서 위다:

| 정밀도 | 양극성 병합 | 접시별 자동 | 차이 |
|---|---|---|---|
| ~88.5% | 60.3% | **63.6%** | +3.3%p |
| ~75.6% | 66.4% | **69.5%** | +3.1%p |
| ~65.3% | 69.0% | **72.8%** | +3.8%p |

**부수 효과로 34% 빨라졌다** (3.16s → 2.10s). 후보는 고른 극성 쪽만 생성하고
무거운 게이트도 한 번만 통과시키기 때문이다. 테스트 전체 실행이 227초 → 57초.

**기각한 판정 방법 — 후보 대비 합산.** 후보 위치에서 (내부−주변)/배경산포 를
합산하는 방식을 먼저 만들었다. 실제 39장에서 39/39 였지만 **합성 이미지에서
틀렸다.** 노이즈가 0이면 배경 산포가 하한(0.5)까지 내려가 정규화 대비가
폭발하고, 합산이라 한 후보가 전체를 지배한다. 후보당 기여를 ±3 으로 클램프해도
고쳐지지 않았다(두 방식 모두 42/43). 흑백 카메라·과노출 클리핑·평탄한 배지에서
같은 조건이 생기고, 극성을 반대로 고르면 검출이 0 에 가까워지므로(실측:
971.jpg 98 → 3) 무시할 수 없는 실패 모드였다.

기존 테스트 `test_finds_colonies_much_larger_than_legacy_kernel` 이 이것을
잡아냈다. 실측 라벨만으로는 통과했을 변경이었다.

### 8.4f 기본 운영점을 재현율 쪽으로 옮겼다 (min_t 35 → 25)

§8.4e 가 정밀도를 5.3%p 벌어줬고, 이 프로젝트 용도는 피킹 대상 확보이므로 그
여유를 재현율로 바꿨다. `param_mapping.sensitivity_to_min_t` 의 앵커도 함께
옮겼다(감도 50 → min_t 25) — 어긋나면 `sensitivity` 를 보내는 클라이언트와
보내지 않는 클라이언트가 다른 감도로 동작하고 눈으로 알아채기 어렵다.

**세션 누적 결과 (39장, 정답 1,886개):**

| | 정밀도 | 재현율 | lower | bright | dark | vague |
|---|---|---|---|---|---|---|
| 세션 시작 | 91.4% | 57.6% | 74.9% | 57.5% | 75.5% | 18.9% |
| solidity 0.75 | 88.6% | 60.3% | 77.0% | 60.7% | 77.7% | 21.1% |

재현율 **+7.6%p**, 네 그룹 전부 개선. `vague` 는 18.9 → 32.5% 로 거의 두 배다.
`vague` 를 제외하면 재현율 약 **71.8%**.

대가는 정밀도 91.4 → 86.4% — 100개 집으면 빈 한천이 약 9개에서 14개로 늘어난다.
오검출 비용이 더 큰 워크플로(시퀀싱까지 가는 경우)라면 `BLOB_MIN_T` 를 35 로
되돌리면 된다(정밀도 93.8% / 재현율 59.5%).

### 8.4h 반지름 보정과 처리 해상도 1280 (2026-08-04)

§8.7 의 "콜로니 반지름 추정 개선" 항목을 처리했다. 표시를 원에서 네모로 바꾸자
문제가 눈에 보였다 — 비슷한 크기의 콜로니에 큰 네모와 점만 한 네모가 섞여 있었다.
원으로 그릴 때는 안 보이던 것이다.

**계통 과소추정 0.71배.** 정답 지름과 비교한 실측(TP 1,707개): 윤곽 기반 중앙
0.73배, LoG 스케일 중앙 0.71배. 25~75% 가 0.65~0.79 로 좁아 산포가 아니라
일관된 편향이다. 원인은 임계값 `(mi+mo)/2` 가 콜로니의 **반높이 지점**을 재기
때문이다.

**라벨 관행이 아니라 검출기가 작았다.** 갤러리에서 눈으로 확인했다 — 초록 정답
박스는 콜로니를 제대로 감싸는데 검출 원은 일관되게 안쪽에 들어가 있다.

**채택: `BLOB_RADIUS_MODE="max"` + `BLOB_RADIUS_SCALE=1.30`.** max 는 꼬리를
고치고(하위 10% 0.51 → 0.64) 배율이 중앙값을 1.0 에 맞춘다. 검출 성적에는
영향이 없다 — 변형 8종 전부 정밀도 86.4~86.8% / 재현율 64.8~65.2% 였다.
**대가로 재현율이 0.3%p 내려간다**(반지름이 커지면 NMS 억제 반경도 커져 밀집
구간의 이웃 일부가 억제된다). 1,886개 중 6개이고, 로봇 핀 배치 정확도와
맞바꿀 값으로 판단했다.

**기각: `BLOB_RADIUS_ALPHA`.** 배경에 가까운 레벨에서 윤곽을 다시 뽑아 외곽을
직접 재는 방식이다. 고정 상수보다 원리적이라 기대했으나 실측이 반대였다 —
중앙값이 0.90 까지만 가고 꼬리도 더 나빴다(하위 10% 0.59 대 곱셈 보정 0.70).
"더 작아지면 무시"와 면적 상한이 낮은 레벨의 윤곽 확장을 막고, 이웃과 붙으면
상한에 걸려 원래 값으로 돌아가기 때문이다. 코드는 기본 끔으로 남겨뒀다.

**adaptive_scale 재평가 — 기각 유지.** §6 은 적응형 해상도를 기각하며 원인을
"크기 추정을 개선하지 않는 한 쓸 수 없다"로 적었다. 크기 추정을 고쳤으므로
다시 쟀는데, 여전히 감도 곡선 **위가 아니라 곡선 위에** 앉는다 — 79.5%/67.3%
인데 같은 정밀도에서 감도만 낮추면 67.8% 다. 적응형 t 문턱과 같은 결말이다.

**채택: `BLOB_WORK_SIZE` 1024 → 1280.** 곡선 전체가 위로 밀린다:

| 정밀도 | 1024 | **1280** | 차이 |
|---|---|---|---|
| ~90.2% | 62.1% | **63.3%** | +1.2%p |
| ~83.3% | 66.3% | **67.6%** | +1.3%p |
| ~76.6% | 68.9% | **70.5%** | +1.6%p |

1536 은 여전히 나쁘다(정밀도 70.8%) — 1280 이 좁은 최적점이고, 보고서가
1024·1536·2048 만 재느라 놓친 구간이었다.

**여기서 함정에 빠졌다 (기록해 둘 가치가 있다).** `BLOB_WORK_SIZE` 를 1280 으로
바꾸면서 `BLOB_R_MIN`/`R_MAX` 를 그대로 뒀더니 정밀도가 83.3% → **73.3%** 로
무너졌다. 검출이 1,529 → 1,739 로 늘고 맞힘은 1,274 그대로 — 순수하게 한천
텍스처만 늘었다.

원인: `detect_blobs` 는 `_k = work_size / BLOB_WORK_SIZE` 로 크기 창을 비례
조정하는데, **기준 상수 자체를 옮기면 `_k` 가 1.0 으로 돌아가** 그 확대가
사라진다. §6 이 1536 을 기각하며 지목한 바로 그 교란을 되살린 셈이다.
크기 창을 1.25배(3.125 / 112.5)로 맞추니 측정값이 정확히 재현됐다.

두 상수는 **반드시 함께 움직여야 한다.** config 주석에 근거와 함께 적어뒀다.

**처리시간은 오히려 줄었다** — 세션 시작 2.3초에서 1.66초. 극성 자동 판정이
게이트를 반으로 줄인 이득이 해상도 증가 비용을 넘는다.

### 8.4i t-통계량 표본 영역 — 이번 세션 최대 개선 (2026-08-04)

`colony_gate` 는 후보 반지름 r 을 기준으로 내부(`d ≤ 0.65r`)와 배경 고리
(`1.4r ~ 2.1r`)에서 표본을 뽑아 t 를 계산한다. **이 세 상수는 blob 경로 도입
이후 한 번도 튜닝된 적이 없었다.**

**채택: inner 0.65 → 0.80, outer_hi 2.1 → 2.8.**

기본 운영점에서 정밀도 83.3 → **87.1%**, 재현율 67.6 → **68.9%**. 같은 정밀도
기준으로는 **+3.6%p** 로, 극성 자동 판정(+3.1~3.8%p)과 맞먹는 이번 세션 최대
단일 개선이다.

**왜 되는가.** t = (mi−mo) / √(s_in²/n_in + s_out²/n_out) 이다. inner 를 넓히면
내부 픽셀이 늘어 분자의 중앙값 추정이 안정되고, 배경 고리를 넓히면 n_out 이 늘어
분모가 줄어든다. 양쪽에서 신호 대 잡음비가 좋아지므로 감도를 옮기는 것과 성격이
다르다 — 그래서 정밀도와 재현율이 함께 오른다.

**곡선 검증** (outer 2.8, 기준선 대비):

| 감도 | 기준선 | outer 2.8 |
|---|---|---|
| min_t 35 | 90.18% / 63.3% | 89.86% / **65.7%** |
| min_t 25 | 83.32% / 67.6% | 84.96% / **69.2%** |
| min_t 20 | 76.64% / 70.5% | **79.64%** / **72.2%** |

세 지점 전부 우세하므로 한 지점의 우연이 아니다. `inner 0.8` 을 얹으면 그
곡선보다 다시 +1.2%p 위다.

**고리 확대가 안전했던 이유.** 넓히면 조명 그라데이션과 이웃 콜로니가 섞일까
우려했으나 실측에서는 2.8~4.2 가 모두 같은 성적이었다(포화). 배경 추정에
중앙값/MAD 를 쓰기 때문이다 — 평균이었다면 독이 됐을 변경이고, §7 에서 로버스트
통계로 바꿔둔 것이 여기서 값을 했다. 안전하게 낮은 쪽인 2.8 을 택했다(고리가
클수록 접시 테두리 밖으로 나갈 여지가 커진다).

**추가 채택: `BLOB_SPLIT_AREA_RATIO` 1.2 → 1.5.** 반지름 보정으로 r 이 1.3배
커져 기대 면적 π r² 이 1.69배가 됐고, 같은 배수가 실질적으로 훨씬 관대해져
분리를 덜 하게 됐다. 곡선 비교에서 세 지점 모두 위다(같은 정밀도 기준 재현율
+0.2~0.9%p, F1 76.9 → 77.2). **한 상수를 옮기면 그것에 의존하는 상수의 보정이
함께 무효가 된다** — 이번 세션에서 세 번째 사례다(work_size↔r_min/r_max,
반지름↔NMS, 반지름↔split_area_ratio).

**같이 재조정했다가 기각한 것:**

| 기각 | 결과 |
|---|---|
| 반지름이 1.3배 커졌으니 `BLOB_NMS_FRAC` 재조정 | **기각.** 0.4~0.8 전 구간에서 재현율 67.4~67.8% / 정밀도 82.4~83.4% 로 평평하다. 반지름이 바뀌어도 이 축은 여전히 무동작이다 |
| 기준선이 달라졌으니 `colour_credit` 재검토 | **기각(재확인).** 같은 정밀도에서 기준 곡선과 ±0.2%p 안에서 겹친다(cc 1.5 → 68.2% 대 곡선 68.3%). 기준선이 90.1%/51.9% 에서 83.3%/67.6% 로 완전히 바뀌었는데도 결론이 같다 |

### 8.4j 후보 생성을 합집합으로 — 이진화가 LoG를 대체하지 않고 보완한다 (2026-08-07)

**질문.** "처음 찾을 때는 이진화가 더 낫지 않나?" OpenCFU를 비롯한 다수 구현이
다중레벨 이진화 + 연결성분으로 후보를 만든다. 우리는 LoG 스케일공간 극값을 쓴다.

**측정.** `threshold_candidates()` 를 구현해(백분위 5~95 를 N등분한 레벨마다
이진화 → 연결성분 → 외접원, 3px 격자 중복제거) 세 방식을 같은 조건에서 비교했다.

| 후보 소스 | 후보 커버리지 |
|---|---|
| LoG 단독 | 93.4% |
| 이진화 단독 | 89.7% |
| **합집합** | **95.4%** |

**둘은 서로 다른 것을 본다.** 각각 93.4%/89.7% 인데 합치면 95.4% 다. 단순
포함관계였다면 합집합이 큰 쪽(93.4%)과 같았을 것이다. 이진화만 잡는 콜로니가
실제로 존재한다는 뜻이다.

이유는 두 방식의 실패 모드가 다르기 때문이다. 전역 임계값은 **밝기가 다른 콜로니를
동시에** 잡을 수 없어 레벨을 여러 개 쓰지만, 어느 레벨에서도 배경과 갈라지지 않는
흐린 콜로니는 끝내 못 잡는다. LoG는 대비가 약해도 **스케일이 맞으면** 반응하지만,
경계가 뚜렷하고 크기가 제각각인 군집에서는 스케일 격자를 벗어난 것을 놓친다.

**곡선 검증** — 한 지점이 아니라 전 구간에서 이겨야 채택한다. 같은 게이트에
후보만 바꿔 넣고 정밀도 구간별 재현율을 재면:

| 정밀도 | LoG 단독 | 이진화 단독 | 합집합 |
|---|---|---|---|
| ~95.5% | 55.1% | — | **58.0%** |
| ~94.1% | 59.0% | **67.3%** | 62.9% |
| ~92.7% | 63.9% | **67.5%** | 67.0% |
| ~88.5% | 68.5% | 68.1% | **72.0%** ← 기본 운영점 |
| ~81.2% | 72.1% | 69.3% | **75.2%** |
| ~65.3% | 74.8% | 71.3% | **77.8%** |

합집합은 LoG 단독보다 전 구간 **+2.9~3.5%p** 다. 채택했다.

**그런데 이 표의 진짜 결론은 따로 있다 — LoG 단독은 어느 구간에서도 최선이 아니다.**
정밀도 93% 이상이면 이진화 단독이, 그 아래면 합집합이 이긴다. 우리가 원래 쓰던
방식이 모든 열에서 지고 있었다는 뜻이다. 사용자의 원래 질문("이진화가 더 낫지
않나?")은 절반 맞았다 — 대체가 아니라 보완이지만, 고정밀 구간에서는 실제로 대체가
맞다.

그래서 세 값을 모두 API에 남겼다. 계수(CFU) 용도처럼 오검출이 비싼 작업에는
`candidate_source: "threshold"` 가 맞다.

**레벨 수는 24에서 포화한다.** 12/24/36 → 재현율 67.9/70.8/71.3%. 늘려도 커버리지
천장(약 90%)이 오르지 않으므로 24를 택했다.

#### 후보 구성이 바뀌자 모양 게이트의 결론이 뒤집혔다

합집합 도입 후 단계별 손실을 다시 재니 **후보 생성은 95.4%를 확보하는데 최종은
72%** 였다. 최대 손실 지점이 후보가 아니라 **모양 게이트**로 옮겨간 것이다.

**채택: `min_circularity` 0.55 → 0.0 (끔).** 같은 감도에서 재현율 74.4 → **75.7%**.

둘레 기반 원형도 4πA/P² 는 **경계 거칠기에 극도로 민감하다.** 합집합 후보의
이진화 성분은 연결성분 윤곽이라 둘레가 톱니처럼 거칠고, 면적이 같아도 P가 커져
원형도가 부당하게 낮게 나온다. LoG 단독 시절에는 후보 윤곽이 매끄러워 이 문제가
드러나지 않았다. **후보 소스를 바꾸면 모양 게이트의 캘리브레이션이 무효가 된다** —
이번 개발에서 네 번째 사례다.

모양 판정은 면적 기반 `min_roundness`(면적 ÷ 최소외접원)가 맡는다. 이쪽은 둘레를
쓰지 않아 거칠기에 둔감하다.

**같은 감도 하향도 채택: `min_t` 25 → 20.** 재현율 72.0 → 74.4%. 정밀도 82.2%는
승인 화면에서 사람이 거를 수 있는 수준이라고 판단했다 — 놓친 콜로니는 되살릴 수
없지만 오검출은 뺄 수 있다.

**기각한 것:**

| 기각 | 결과 |
|---|---|
| 세 번째 후보 소스로 MSER 추가 | **기각.** 이진화와 같은 것을 본다 — 합집합 커버리지가 95.4%에서 움직이지 않았다 |
| 채도 채널 후보 추가 | **기각.** 무채색 접시가 다수라 기여가 없고 유채색 접시에서는 오검출만 늘었다 |
| `work_size` 1536 재시도 | **기각.** 후보 구성이 바뀌었으니 다를까 했으나 여전히 전 그룹에서 나쁘다 |
| `min_roundness` 완화 (0.45/0.35/0.25) | **기각.** 곡선이 아래로 밀린다. 정밀도 82.8% 기준 0.45는 72.5%, 기본값 유지는 74.7% (**−2.2%p**) |
| `min_solidity` 완화 (0.65/0.55) | **기각.** 결과가 완전히 동일 — 0.75 아래는 포화 |
| `min_fill` 0.60 상향 | **조건부.** 정밀도 92~96% 구간에서만 +1.4~2.1%p. 기본값으로는 부적합하나 계수 용도에 유효하므로 API에 남겼다 |

**둥글기 완화 기각은 세 번째 외삽 오류를 잡은 사례다.** 단계별 손실 분석이 모양
게이트를 최대 손실로 지목했으니 완화가 당연해 보였고, 한 지점만 보면 실제로
재현율이 올랐다(0.45 t20 → 77.8%). 그러나 정밀도가 84.3 → 72.4%로 떨어진 것이라
같은 정밀도로 맞추면 오히려 손해였다. **손실 분석은 어디를 볼지 알려주지만 무엇을
할지는 알려주지 않는다.**

### 8.5 수작업 게이트는 한계에 도달했다 (당시 판단 — 이후 뒤집혔다)

> **정정 (2026-08-07).** 이 절은 F1 66 시점의 기록이다. 결론이었던 "남은 성능
> 격차는 파라미터 조절로 닿을 수 없다"는 **틀렸다.** 이후 §8.4c~8.4j 에서
> 파라미터·후보구성 변경만으로 F1 66 → **78.8**, 재현율 57.6 → **75.7%** 에
> 도달했다.
>
> 무엇을 잘못 봤나: 당시 평평했던 축들(NMS, LoG 문턱, solidity)은 실제로 평평한
> 게 맞았다. 오류는 **"내가 시도한 축이 평평하다"에서 "축이 남지 않았다"로
> 건너뛴 것**이다. 정작 컸던 세 개 — t-통계량 표본 영역(§8.4i, +3.6%p), 극성
> 자동판정(§8.4h, +3.1~3.8%p), 후보 합집합(§8.4j, +2.9~3.5%p) — 는 그때
> 시도하지 않은 축이었다. 특히 표본 영역 상수는 blob 경로 도입 이후 **한 번도
> 튜닝된 적이 없었다.**
>
> 아래 내용은 당시 측정으로서 유효하므로 그대로 둔다.

측정으로 확인된 사실: **추가한 모든 축이 정밀도/재현율 교환일 뿐이고, 어느 것도
다른 것을 지배하지 않는다.** Pareto 전선이 F1 66 부근에 있다.

| 시도한 축 | 재현율 이득 | 정밀도 대가 |
|---|---|---|
| t 하한 낮추기 (35→25) | +3.3%p | −11.8%p |
| 원형도 게이트 해제 | +2.8%p | −6.8%p |
| 색 할인 2배 | +10.4%p | −29.5%p |
| 해상도 1536 (크기창 고정) | +3.7%p | −22.6%p |

무료였던 것은 두 개뿐이고 이미 반영했다 — ROI 수축 0.94→0.98, 채도 문턱 3.0→1.5
(합쳐서 재현율 +2.1%p, 정밀도 −0.4%p).

**평평해서 조절 가치가 없는 축** (전 구간에서 F1 차이가 노이즈 수준):

| 축 | 결과 |
|---|---|
| NMS 억제반경 | 0.5 ~ 1.1배 전부 F1 65.7~65.8 |
| LoG 후보 문턱 | 0.4 / 0.8 / 1.6 에서 **결과가 완전히 동일** — t 게이트가 지배 |
| LoG 스케일 수 | 12 → 65.5, 16 → 65.7, 22 → 65.5 |
| solidity·종횡비·채움율 게이트 | 진짜 콜로니를 2개만 버림 (사실상 무해·무익) |

이 축들이 평평하다는 것은 **파이프라인이 이 파라미터들에 대해 이미 포화**됐다는
뜻이다. 남은 성능 격차는 파라미터 조절로 닿을 수 없다.

### 8.6 학습 기반 판정기 — 시도했고 기각

수작업 게이트가 Pareto 전선에 도달했으므로 학습된 판정 경계를 시도했다.
근거: 현재 AND 사슬은 특징 공간에서 **축에 평행한 절단**만 만들므로, 여러 약한
특징의 조합이 만드는 비스듬한 경계를 표현할 수 없다.

**데이터.** 후보 220,839개(양성 10.4%), 이미지 39장, 특징 16개
(t-통계량·대비·면적·상대크기·상대채도·hue거리·원형도·둥글기·solidity·종횡비·
채움율·방사단조·경계일관·국소노이즈·내부픽셀수·극성).

**검증 규칙.** 이미지 단위 5-fold, 촬영조건별 층화. 같은 접시의 콜로니는
조명·배지·균주를 공유하므로 콜로니 단위 분리는 검증을 무의미하게 만든다.
표준화 통계와 계수는 학습 fold 에서만 구했다. 의존성은 늘리지 않았다 —
로지스틱 회귀와 히스토그램 기반 경사부스팅을 numpy로 직접 구현했다.

**결과 (콜로니 단위, NMS·1:1 매칭 후).**

| 판정기 | 정밀도 | 재현율 | F1 |
|---|---|---|---|
| **수작업 AND 게이트** | **90.4%** | **51.2%** | 65.4 |
| 로지스틱 회귀 (문턱 0.95) | 87.0% | 43.0% | 57.6 |
| 로지스틱 회귀 (문턱 0.90) | 69.1% | 61.3% | 65.0 |
| GBM (문턱 0.98) | 89.1% | 43.2% | 58.1 |
| GBM (문턱 0.95) | 69.4% | 64.7% | **67.0** |
| GBM (문턱 0.995) | 99.7% | 16.6% | 28.5 |

**같은 정밀도(89~90%)에서 두 학습 모델 모두 재현율이 낮다** (43% 대 51%).
따라서 피킹 용도에서는 수작업 게이트가 우세하고, 기본 경로로 유지한다.

로지스틱 회귀가 진 이유는 구조적이다. AND 사슬은 "이 조건들이 **모두** 성립"
이라는 비선형 영역인데 선형 모델은 직선 경계 하나만 그린다 — 이 문제에서는
선형 모델이 오히려 **표현력이 부족**하다. 그래서 논리곱을 자연히 표현하는
트리(GBM)로 재시도했고, GBM은 F1 정점을 65.4 → **67.0**으로 올렸지만 그 지점의
정밀도가 69.4%다.

**단, 용도가 CFU 계수라면 결론이 뒤집힌다.** 균형 F1이 중요하고 정밀도를 다소
포기할 수 있다면 GBM 문턱 0.95(69.4%/64.7%, F1 67.0)가 현재 게이트보다 낫다.
학습·평가 스크립트는 재현 가능하게 남겨두었다.

**놓치기 쉬운 함정.** 후보 단위 지표만 보면 학습 판정기가 같은 재현율에서
정밀도 94.3% 대 91.6%로 **이기는 것처럼** 보였다. 그러나 콜로니 하나에 후보가
평균 20여 개 붙고 그중 하나만 살아남으면 검출 성공이므로, 후보 단위 지표는
실제 성능과 무관하다. NMS와 1:1 매칭을 거친 뒤에만 비교가 성립한다.

### 8.6a Cellpose — 품질은 유의하게 높다 (2026-07-29, 예비)

§8.6 에서 기각한 것은 **손으로 만든 특징 위의** 학습 판정기(로지스틱·GBM)다.
픽셀에서 특징을 직접 배우는 세그멘테이션 모델은 다른 이야기이고, 실제로 달랐다.

`5271.jpg` 한 장, **같은 매칭 규칙**으로:

| | 검출 | 맞힘 | 정밀도 | 재현율 |
|---|---|---|---|---|
| **Cellpose-SAM 384px (사전학습, 학습 없음)** | 39 | 39 | **100.0%** | **90.7%** |
| blob 경로 (현재 기본값) | 30 | 29 | 96.7% | 67.4% |

**재현율 +23.3%p, 정밀도 +3.3%p.** 오검출이 0이다. 그리고 이 수치는 원본 4000px 를
10분의 1로 줄인 **384px** 에서 나왔다 — 우리가 1024px 에서 하는 것보다 낫다.

**주의: 한 장이다.** 결론을 내리기 전에 네 조건 모두에서 재야 한다. 특히 `vague`
(우리 18.9%)에서 유의하게 높은지가 전체 90% 달성 가능성을 가른다.

**GPU 판단:** 이 신호가 여러 장에서 유지되면 GPU 도입이 정당화된다. CPU 384px 가
292~399초이므로 GPU 로 10~20배면 15~40초 — 접시당 한 번이면 운용 가능하다.
반대로 신호가 유지되지 않으면 하드웨어를 살 이유가 없다. **그래서 CPU 로 먼저
측정한다** — 품질 측정에 GPU 는 필요 없다.

### 8.6b Cellpose — 네 그룹 CPU 측정 결과 기각 (2026-08-03)

§8.6a 의 한 장짜리 신호(`5271.jpg` 정밀도 100% / 재현율 90.7%)를 근거로 네 그룹
전부에서 측정했다(12장, 정답 406개, `--work 384`). **신호가 재현되지 않았다.**

품질이 나오지 않는다. 원인 규명 없이 재시도할 이유가 없다.

### 8.6c OMNI TRAY (사각 단일 웰) — 미지원

`plate_type` 은 `petri`(원형)와 `well8`(4×2 몰딩)뿐이다. OMNI TRAY 같은 **사각
단일 웰**은 둘 다 아니다. 합성 트레이(콜로니 54개 균등 배치)로 확인한 결과:

| plate_type | 검출 | 문제 |
|---|---|---|
| `petri` | 21 / 54 | 사각형에 원을 끼워 넣어 **한천 면적의 33%만** ROI |
| `well8` | 16 / 54 | 트레이를 8칸으로 잘라 격자선 영역을 버림 |

`plate_type="tray"` 추가가 필요하다 — 사각 경계 검출 후 안쪽 수축, 크기 기준
길이를 접시 지름 대신 트레이 짧은 변으로. 구현 난이도는 낮다.

**단 검증할 이미지가 없다.** 합성으로는 ROI 정확성까지만 확인 가능하고 실제
검출률은 알 수 없다. 실제 트레이에는 합성으로 재현 못 하는 것들이 있다 —
모서리 그림자, 뚜껑 반사, 사각 모서리 메니스커스(원형과 패턴이 다르다), 스티커.

### 8.7 그래서 다음에 할 일

우선순위 순으로, 근거와 함께.

0. **`vague` 조건 촬영 개선** — 90% 재현율로 가는 **유일한 길**이다. 그 그룹이
   정답의 17%(317개)인데 재현율 18.9%이고, 놓침의 84%가 t-통계량 실패다.
   국소 대비가 256단계 중 2~3단계라 알고리즘으로 메울 격차가 아니다.
   **그 그룹을 그대로 두면 전체 재현율의 산술적 상한이 85.9%다** — 나머지 세
   그룹을 100% 완벽하게 만들어도 그렇다. 조명·배지 대비를 10~20단계로만 올리면
   다른 그룹처럼 75%대가 나오고 전체가 70%대가 된다.

1. **8웰 플레이트 라벨 확보** (§8.4). 이 프로젝트 실제 하드웨어인데 측정 자체가
   불가능한 상태다. 10~20장이면 충분하고, `sample/`과 같은 JSON 형식이면
   `scripts/evaluate_labeled.py`가 그대로 읽는다. 지금은 그 포맷에서 blob 경로가

2. **오퍼레이터 승인 화면** — 알고리즘이 아니라 제품 쪽 과제인데 효과는 가장
   크다. 현재 정밀도 82.2% 는 **검출 5~6개 중 1개가 빈 한천**이라는 뜻이고,
   재현율 75.7% 는 **4개 중 1개를 놓친다**는 뜻이다. 사람이 클릭 두 번으로
   빼고 더할 수 있으면 로봇에 가는 목록의 실질 품질은 100%에 가까워진다.
   알고리즘으로 이 격차를 메우려면 §8.6 이 보여주듯 훨씬 비싸다.
   → [react-integration.md](react-integration.md) §5

3. **OMNI TRAY 를 쓸 계획이면 `plate_type="tray"` 구현** (§8.6c). 지금은 절반
   이상을 놓친다. 구현 난이도는 낮지만 트레이 이미지 없이는 검증할 수 없다.

4. **CFU 계수 모드** — 계수 용도가 생기면 두 가지가 이미 준비돼 있다.

   기본값과 별도 모드로 두면 된다.
