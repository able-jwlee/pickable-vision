화면 목업 서버 없이 열린다 — 실제 샘플 접시의 실제 검출 좌표를 파일에 담았다. 크기 축과 중첩 제외는 화면에서 바로 반영되고, 나머지 축은 서버 재검출이 필요하므로 그 상태를 그대로 보여준다. 필드 매핑은 페이지 맨 아래 개발자 노트에 있다.

즉시 반영 vs 재검출

        

          크기와 exclude_nested 만 클라이언트에서 반영할 수 있다.
          크기는 근사다 — 서버에서는 검출 게이트에 들어가므로 결과가
          완전히 같지 않다. 그래도 미리보기를 주는 편이 낫고, 실제 값은
          재검출로 확정한다.
        

        

          나머지 축을 바꾸면 화면 결과가 낡는다. 오버레이를 흐리게 하고
          "다시 검출" 을 강조할 것. 값만 바뀌고 화면은 그대로인 상태를
          방치하면 오퍼레이터가 잘못된 결과를 승인한다.
        

      


      

        
색상 그룹 잠금

        

          applied_params.has_chroma === false 면 서버가 색 축을 끈
          것이다(흑백 카메라·채도 없는 입력). 그때
          min_rel_sat 은 무동작이므로 그룹을 잠그고 이유를 보여줘야
          한다. 잠그지 않으면 슬라이더를 움직여도 결과가 안 바뀌는 이유를 알 수
          없다.
        

      


      

        
크기 히스토그램 데이터

        

          별도 API 가 없다. 응답의 colonies 에서 바로 만든다 —
          x 축은 diam_frac 을 그대로 쓴다 (1.4.0 신규).
        

        

          radius × 2 ÷ plate_size_ref 로 계산하지 말 것.
          이 문서가 1.3.0 까지 그렇게 안내했는데 틀렸다. radius 는
          표시용이라 크기 게이트가 본 값에 보정(radius_mode,
          radius_scale)이 붙어 있고, 그 배수가 검출마다 다르다 —
          실측 39장·2175건에서 중앙 1.39 · p95 2.16 · 최대 7.73. 상수가
          아니라 나눠서 되돌릴 수 없다. 그래서 히스토그램이 크기 창 슬라이더보다
          오른쪽으로 밀려 보였다.
        

        

          diam_frac 은 게이트가 실제로 비교한 값이라 슬라이더와
          같은 축에 놓인다. 대신 화면의 원보다 작다 — 눈으로 잰 지름이 아니다.
          마커 크기는 계속 radius 를 쓸 것. 둘은 용도가 다르다.
        

        
const frac = c.diam_frac * 100

applied_params 를 그대로 표시

        

          sensitivity → min_t 매핑을 클라이언트에서 재계산하지 말
          것. 서버가 적용한 값이 응답에 그대로 온다. 이 프로젝트는 표시값이
          서버와 어긋나는 문제를 네 번 겪었고 원인은 매번 "복제본을 안 고침"
          이었다.
