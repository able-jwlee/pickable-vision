기준 · 감도

슬라이더를 40~85 로 좁힌다

권고
현재min=0 max=100 전 구간
변경min=40 max=85

매핑이 비대칭이라 50 아래는 한 칸이 min_t 1.4 씩, 위는 0.16 씩 움직인다. 실측점이 있는 구간은 43~81 뿐이고 그 아래는 측정한 적이 없다. 슬라이더 왼쪽 절반이 사실상 쓸 수 없는 구간이라 오퍼레이터가 실수로 들어가기 쉽다.

범위를 좁히기 싫으면 전 구간을 두되 43~81 밖에서 “측정 범위 밖” 배지를 띄우는 것도 된다. 둘 중 하나는 해야 한다.

2

크기 · 히스토그램

88% 근사를 버리고 서버가 준 분모를 쓴다

필수

이게 이번 변경의 핵심이다. 접시 지름이 응답에 없어서 지금은 이미지 짧은 변의 88% 로 어림하고 있다. 이제 서버가 실제로 쓴 기준 길이를 applied_params.plate_size_ref 로 돌려준다 — 크기 축의 모든 숫자가 근사에서 정확한 값이 된다.

// 지금
const dishD = Math.min(width, height) * 0.88
const frac  = (c.radius * 2) / dishD * 100

// 변경 — 서버가 실제로 쓴 분모
const dishD = applied.plate_size_ref
const frac  = (c.radius * 2) / dishD * 100

서버가 min_diam_frac 을 판정할 때 쓰는 분모와 같은 값이다. 그래서 화면의 히스토그램 눈금과 실제로 잘리는 지점이 처음으로 일치한다.

88% 어림의 오차 · 실측 10장

일정한 편향이 아니라 이미지마다 다르다. 어림이 최대 11.7% 크게, 최대 5.8% 작게 잡힌다. 방향이 일정하면 보정 상수로 덮을 수 있지만 그렇지 않다 — 접시가 프레임을 채운 정도가 촬영마다 달라서다. 그래서 오퍼레이터가 “최소 지름 5%”로 맞춘 값이 접시마다 다른 물리 크기를 뜻하게 된다.

주의. petri 에서 접시 검출이 성공했을 때만 접시 지름이다. well8 이거나 검출이 실패하면 서버도 이미지 짧은 변으로 폴백하고, 프레임보다 큰 값이 나올 수도 있다. 그러니 환산에만 쓰고 “접시 지름 N mm” 처럼 물리량으로 표시하지 말 것.

3

크기 · 최대 지름

최대 지름을 고급으로 내린다

권고
현재최소·최대가 나란히 항상 보임
변경최소만 노출, 최대는 접힘 안으로

실측 콜로니 지름이 접시 지름의 1.2~45% 로 매우 넓다. 상한을 어디에 두든 진짜 큰 콜로니를 버린다. 게다가 상한이 막으려는 대상(뭉친 덩어리·접시 테두리)은 이미 watershed_split 과 접시 반지름 수축이 담당한다. 하한은 한천 텍스처를 자르는 데 실제로 쓸모가 있어서 남긴다.

4

경계 여백이 있는 화면

mask_walls 가 꺼져 있으면 여백을 잠근다

필수

경계 여백(edge_margin)은 mask_walls 가 꺼져 있으면 아무 일도 하지 않는다. 지금까지는 응답에 pick_edge_margin 만 있어서 그게 적용됐는지 알 방법이 없었다. 이제 mask_walls 도 같이 온다 — has_chroma 로 색 축을 잠그는 것과 똑같이 처리하면 된다.

<fieldset disabled={!applied.mask_walls}>
  {!applied.mask_walls && (
    <p>경계 제한이 꺼져 있어 적용되지 않습니다.</p>
  )}
  {/* 경계 안전 여백 슬라이더 */}
</fieldset>

이 패널에 여백 컨트롤이 안 보이는데, 마무리 단계에 있다면 거기에 적용할 것.

자동

피킹 대상 선택

96핀이 고르는 콜로니가 실제로 바뀐다

확인만

피킹 순위(score)의 고립도 항이 원본 픽셀 상수 50px 기준이라 해상도에 의존했다. 고해상도 접시에서는 이웃 거리가 대부분 50px 를 넘어 고립도가 상수로 포화했고, 크기 항도 기본값에서 상수라 — 실제로 순위를 정한 것은 원형도 하나였다. 자기 반지름의 6배 기준으로 바꿔 해상도와 무관해졌다.

접시고립도 포화 전 → 후영향
성긴 접시 16~32개100% → 24~56% 검출이 96보다 적어 목록은 같고 순서만 바뀜
밀집 접시 439개57.6% → 2.7% pick_top_n 96 중 62개가 다른 콜로니로 교체

UI 가 할 일은 확인뿐이다. score 를 화면에 표시하거나 정렬에 쓰고 있다면 값이 달라진 것을 알고 있을 것. 붙은 콜로니를 집으면 두 균주가 섞인 혼합 클론이 되므로, 고립된 것이 먼저 뽑히는 게 맞는 동작이다.
