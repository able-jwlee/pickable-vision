# 용기 전략 분리 (`plate_type`) — 설계

**작성일:** 2026-07-28
**선행 조사:** [2026-07-28-sample-accuracy-investigation.md](../2026-07-28-sample-accuracy-investigation.md)

---

## 1. 배경

검출 파이프라인이 4×2 웰 플레이트 한 종류를 전제로 짜여 있다. `_well_mask`가 이미지를
2행 4열 격자로 잘라 각 셀 내부만 남기는데, 원형 페트리 접시에는 이 격자가 의미가 없다.
접시 이미지 39장 평가 결과 정밀도 0.85%, 재현율 33.0%로 무작위 산포(재현율 56.7%)보다
나빴다. 검출이 접시 테두리 링과 뚜껑 유성펜 글씨에 고착돼 있었다.

`sample/` 40장은 실제 웰플레이트를 촬영하기 전에 확보한 **대역 데이터**이며 목표 도메인이
아니다. 목표 도메인은 웰 플레이트다.

## 2. 목표와 비목표

**최종 목표(사용자 명시):** 콜로니 검출률과 정확도를 높인다.

이번 작업이 그 목표에 기여하는 방식:

- 용기 종류에 따라 ROI 산출을 갈아끼울 수 있는 seam을 만든다 — 이후 정확도 개선을
  용기별로 독립 수행할 수 있게 된다.
- 페트리에서 가장 큰 오검출원(접시 밖 영역, 테두리 링)을 제거한다.
- **라벨 기반 정밀도/재현율 측정 수단을 리포에 상설화한다.**

**정직한 한계:** 이번 작업은 **웰 플레이트 정확도를 올리지 못한다.** 목표 도메인의
라벨 데이터가 하나도 없어(리포 내 웰플레이트 이미지는 `tests/fixtures/agar_sample.jpg`
한 장, 라벨 없음) 개선 여부를 측정할 방법 자체가 없다. 실제 촬영본이 확보되고 라벨링이
끝나야 정확도 작업을 시작할 수 있다. 이번 작업은 그 준비 단계다.

**비목표 (이번 범위 제외):**

- 해상도 정규화 — 조사 문서 §6에 보류 위험으로 기록됨
- 페트리 정확도 목표치 설정
- 뚜껑 글씨·기재 사항 제거
- 학습 기반 검출

## 3. 설계

### 3.1 분리 지점

`detector.py`는 두 종류의 관심사가 섞여 있다.

| 용기 의존 | 용기 무관 |
|---|---|
| `_plate_roi`, `_well_mask`, `pick_region` | top-hat → Otsu → 열림 → 메니스커스 제거 → watershed → contour 필터 |

용기 의존 부분만 전략으로 분리한다. 검출 알고리즘 본체는 손대지 않는다.

### 3.2 모듈 구조

```
app/plates/
  __init__.py   — get_plate(name) 레지스트리
  base.py       — PlateStrategy 프로토콜
  well8.py      — 기존 _plate_roi / _well_mask 를 로직 변경 없이 이동
  petri.py      — 원형 ROI (신규)
```

```python
class PlateStrategy(Protocol):
    name: str

    def roi(self, gray: np.ndarray) -> np.ndarray:
        """검출 대상 영역 마스크. 255=대상, 0=제외."""

    def default_invert(self, gray: np.ndarray, roi: np.ndarray) -> bool:
        """요청에 invert가 없을 때 쓸 명암 극성."""
```

`get_plate("well_8")` / `get_plate("petri")`. 알 수 없는 이름은 `ValueError` →
API에서 400으로 변환.

### 3.3 well8 전략

기존 `_plate_roi`, `_well_mask` 를 **그대로 옮긴다.** 상수도 `config`에 그대로 둔다.
`default_invert`는 이미지와 무관하게 `config.DEFAULT_INVERT`(True)를 반환한다.

로직이 바뀌지 않으므로 웰 플레이트 경로에 회귀 위험이 없다. 이것이 이 설계의 핵심
안전장치다 — 목표 도메인을 측정할 수 없는 상태이므로, 목표 도메인 코드를 건드리지 않는다.

### 3.4 petri 전략

**ROI (원형 접시 검출):**

1. 긴 변 기준 1000px 이하로 다운스케일 (속도)
2. Otsu 이진화. 접시가 배경보다 밝을 수도 어두울 수도 있으므로 **양 극성 모두** 시도해
   최대 윤곽을 잡고, `면적 / (π r²)`가 큰 쪽(원에 더 꽉 찬 쪽)을 채택
3. `cv2.minEnclosingCircle` 로 접시 원 추정
4. 원본 좌표로 환산, 반지름에 `PETRI_RIM_MARGIN_RATIO`(기본 0.93)를 곱해 안쪽으로 수축
   — 테두리 링과 접시 벽을 제외
5. 그 원을 채운 마스크 반환

**채택 조건:** `채움비 > 0.85` 이고 반지름이 긴 변의 15~75% 범위. 벗어나면 접시를 못
찾은 것으로 보고 **전체 이미지 마스크로 폴백**하며 `applied_params.petri_roi_found=false`를
실어 호출자가 알 수 있게 한다.

**프로토타입 실측 (라벨 39장):**

| 지표 | 값 |
|---|---|
| 접시 원 검출 성공 | 31 / 39 (라벨 없는 1399 포함 시 32 / 40) |
| 그중 정답 콜로니를 98% 이상 보존 | 26 / 39 |
| 성공 시 제거되는 배경 면적 | 41 ~ 64% |
| ROI 밖으로 잘려나간 정답 콜로니 | 대부분 0%, 최대 4.8% (5212.jpg) |

콜로니를 거의 잘라내지 않으면서 배경 절반가량을 지운다. 검출 실패 8장은 전체 이미지
폴백이므로 현재 동작 대비 손해가 없다.

콜로니가 4~5% 잘리는 5장(510, 971, 5212, 5271, 12033)은 접시 가장자리에 붙은 콜로니가
`RIM_MARGIN_RATIO=0.93` 수축에 걸린 경우다. 이 비율은 테두리 링 제거와 가장자리 콜로니
보존 사이의 트레이드오프이므로 구현 시 조정 가능하게 둔다.

**극성 자동 추정 (`default_invert`):**

ROI 내부 픽셀 분포의 치우침으로 판정한다. 콜로니는 소수 픽셀이므로, 콜로니가 배경보다
밝으면 분포가 오른쪽으로 꼬리를 단다.

```
invert = not (mean(roi_pixels) > median(roi_pixels))
```

**프로토타입 실측: 30 / 39 (77%).** 틀린 9장은 전부 콜로니와 배경의 밝기 대비가
±1 계조 이하인 이미지로, 극성 자체가 모호한 경우다. 대비가 뚜렷한 이미지에서는
모두 맞았다.

77%는 자동에만 의존하기엔 부족하므로 **명시적 `invert` 지정이 신뢰 경로**임을 문서화한다.
자동 추정은 미지정 시의 합리적 기본값 역할만 한다.

극성은 그룹과 무관하게 섞여 있다(실측: bright 그룹 9장 중 8장이 어두운 콜로니,
lower-res 10장 전부 밝은 콜로니, vague는 4:6으로 혼재). 그룹명으로 극성을 추정할 수 없다.

### 3.4.1 페트리 예상 성능 — 실측 기반

프로토타입 ROI를 실제 검출 결과에 적용해 39장 전체에서 측정했다
(기준선은 `mask_walls: false`, 즉 ROI 없는 상태).

| 지표 | ROI 없음 | ROI 적용 |
|---|---:|---:|
| 검출 수 | 150,738 | 100,509 |
| 맞힌 것 (TP) | 832 | 822 |
| **정밀도** | 0.55% | **0.82%** |
| **재현율** | 44.1% | **43.6%** |

**정밀도가 1.5배 오르고 재현율은 유지된다. 그러나 여전히 1% 미만이다.**

이유는 명확하다 — 지배적 오검출원(뚜껑 유성펜 글씨, 콜로니 표면 질감, watershed
과분할)이 **접시 안에** 있어서 ROI로 걸러지지 않는다.

**따라서 이 작업 후에도 페트리 검출은 실사용 가능한 정확도가 되지 않는다.** 이는
합의된 범위(구조 seam + best-effort, 정확도 목표 없음)와 일치하며, 스펙 §2의
비목표를 재확인한다. 페트리를 실제로 쓰려면 뚜껑 기재 제거, 질감 억제, watershed
재설계가 추가로 필요하고 그건 별도 과제다.

### 3.5 API 변경

`DetectRequest`:

```python
plate_type: Literal["well_8", "petri"] = "well_8"
invert: bool | None = None      # None = 전략이 결정
```

`invert` 타입 변경이 유일한 기존 필드 수정이다. **기존 동작과 동일함**을 보장한다:

| 요청 | 기존 | 변경 후 |
|---|---|---|
| `invert` 미지정 | `True` (config 기본값) | `well8.default_invert()` → `True` |
| `invert: false` | `False` | `False` (명시 우선) |
| `invert: true` | `True` | `True` (명시 우선) |

`mask_walls`는 그대로 둔다. `False`면 ROI를 적용하지 않는다 (전략 무관).

`DetectResponse.applied_params`에 `plate_type`, 확정된 `invert`, `petri_roi_found`
(petri일 때만)가 추가된다.

오퍼레이터 0~100 슬라이더 4개는 변경 없다.

### 3.6 데이터 흐름

```
DetectRequest
  → get_plate(req.plate_type)               전략 선택
  → strategy.roi(gray)                       ROI 마스크 (mask_walls=True일 때)
  → invert = req.invert if not None
             else strategy.default_invert()  극성 확정
  → detect(...)                              기존 알고리즘, 변경 없음
  → score_colonies(...)                      기존, 변경 없음
  → DetectResponse
```

`pick_region()`도 전략의 ROI를 쓰도록 바꾼다 — 현재 `_well_mask`를 직접 부르고 있다.

## 4. 검증 계획

### 4.1 회귀 (웰 플레이트 경로 무변경 증명)

- 기존 74개 테스트가 **한 줄도 수정 없이** 통과해야 한다.
- 신규: `plate_type` 미지정 요청과 `plate_type: "well_8"` 요청이 **콜로니 리스트 전체
  동일**(개수가 아니라 `colonies` 배열 equality). fixture로 검증.
- 신규: 리팩터 전 fixture 검출 결과를 골든 값으로 고정해, 이동한 코드가 동작을 바꾸지
  않았음을 확인.

### 4.2 페트리 ROI 동작

정확도 목표가 아니라 **ROI가 작동한다는 측정**이다.

- `13895.jpg`, `349.jpg`에 `plate_type: "petri"` 적용 시, 추정 접시 원 **바깥** 검출
  개수가 0에 수렴.
- 극성 자동 추정이 `dark` 그룹 10장에서 `invert=False`, `bright` 그룹에서 `invert=True`를
  고르는지 확인.
- 접시를 못 찾는 이미지에서 `petri_roi_found: false`가 실리는지.

### 4.3 측정 수단 상설화

조사에 쓴 평가 하네스를 `scripts/evaluate_labeled.py`로 리포에 넣는다.

- 입력: 라벨 json이 동반된 이미지 디렉터리
- 출력: 이미지별·전체 정밀도/재현율/F1
- **CI 게이트를 걸지 않는다.** 페트리는 목표 도메인이 아니고, 웰플레이트는 라벨이 없다.
  측정 수단만 확보해 두고, 실제 웰플레이트 라벨이 생기면 같은 명령으로 잰다.

기준선으로 현재 페트리 수치(기본값 정밀도 0.85% / 재현율 33.0%)를 문서에 남기고,
petri 전략 적용 후 수치를 같은 표에 병기한다. §3.4.1의 프로토타입 실측치가 예상
착지점이다.

**성공 판정:** "정밀도가 목표치를 넘었는가"가 아니라 다음 세 가지다.

1. 기존 74개 테스트 무수정 통과 (웰플레이트 무회귀)
2. `plate_type: "petri"` 적용 시 정밀도가 기준선보다 **오르고** 재현율이 떨어지지 않음
3. `scripts/evaluate_labeled.py` 한 줄로 정확도를 잴 수 있음

## 5. 목업 정리

**2026-07-28 사용자 방향 전환.** 초기 설계에서는 정답 박스 SVG 오버레이 + delta caveat
을 추가할 계획이었으나, 오퍼레이터 UI 는 **정답 관련 표시를 넣지 않는 방향으로 변경**됐다.
새 컨셉: 필터 파라미터 조절 → [검출] → [로봇에 전송]. 검출된 콜로니는 전부 피킹 대상이며
색으로 구분하지 않는다.

**반영된 변경:**

- 정답 개수(`stat-gt`), delta chip, 개수-일치 caveat 전부 제거
- min/max 크기 슬라이더 2개를 **단일 "콜로니 크기" 슬라이더**로 통합 (내부적으로
  `min_size = V`, `max_size = clamp(V + 55, 75, 100)` 로 벌림 → V=20 기본값에서 기존
  검출 결과 그대로 유지)
- pickable/non-pickable 색 구분 제거 (모두 초록 원)
- `plate_type` 드롭다운 (`well_8` 기본 / `petri`) 추가 — payload 에 실림 (서버는 §5
  구현 전까지 Pydantic `extra='ignore'` 로 무시)
- [로봇에 전송] 버튼 추가 (목업 전용 — 좌표 요약을 콘솔에 찍고 alert)

**개편이 남긴 함정:** 목업에서 위치 검증 수단을 뺐으므로, 정확도 튜닝은 **`scripts/
evaluate_labeled.py`** 를 통해서만 확인 가능하다. 목업의 [검출] 결과 개수만 보고
"잘 맞고 있다"고 판단하면 안 된다 (13895.jpg 의 검출 19 = 정답 19, 실제 맞힘 0 사례
가 그대로 재현된다). §6-1 실제 웰플레이트 라벨 확보 후 별도 스크립트로 잰다.

## 6. 결정 로그

| 항목 | 선택 | 근거 |
|---|---|---|
| 용기 판별 | 요청 파라미터 (`plate_type`) | 운영 대상이 웰플레이트로 확정 — 런타임 자동 판별의 오판 위험을 질 이유가 없음 |
| 페트리 범위 | 구조 seam + best-effort | `sample/`이 대역 데이터라 정확도 최적화는 목표 아닌 도메인에 대한 낭비 |
| well8 구현 | 코드 이동만, 로직 무변경 | 목표 도메인 정확도를 측정할 수 없으므로 건드리지 않는 것이 유일한 안전장치 |
| `invert` | `bool \| None` | 전략이 극성을 정하되 명시 지정이 우선. 기존 동작 보존 |
| 해상도 정규화 | 제외 | 사용자 지시. 조사 문서 §6에 보류 위험으로 기록 |
| 평가 게이트 | 걸지 않음 | 목표 도메인 라벨 부재. 측정 수단만 확보 |

## 7. 후속 (이번 범위 밖)

1. **실제 웰플레이트 촬영본 확보 및 라벨링** — 정확도 작업의 전제조건. 이게 없으면
   무엇을 바꿔도 개선 여부를 알 수 없다.
2. 해상도 정규화 (조사 문서 §6)
3. 뚜껑 글씨·기재 제거
4. 라벨 1,886개를 활용한 학습 기반 검출 검토
