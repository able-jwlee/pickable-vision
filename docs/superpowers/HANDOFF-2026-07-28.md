| 추상 필드 (0~100) | 덮어쓰는 raw | 기본값 → raw | 매핑 |

| `edge_margin` | `PICK_EDGE_MARGIN` | 40 → 60px | `margin = v·1.5` |

  - 버튼: [기본값으로] [검출] / [로봇에 전송 (좌표 N개, 검출 후 활성)]

## 4. 발견된 문제 — 검출기가 `sample/`에서 동작하지 않음

**전체 조사서: [2026-07-28-sample-accuracy-investigation.md](2026-07-28-sample-accuracy-investigation.md)**

### 4.1 측정 결과

각 이미지 동반 json에 콜로니 바운딩 박스가 있다(39/40장, 1399만 미라벨). 좌표 대조 결과:

| 지표 | 값 |
|---|---|
| 정답 콜로니 | 1,886개 |
| 검출 | 73,402개 |
| 맞힘 | 622개 |
| **정밀도** | **0.85%** |
| **재현율** | **33.0%** |

**같은 개수의 점을 무작위로 뿌리면 1,070개(재현율 56.7%)를 맞힌다.** 검출기가 무작위보다
나쁘다 — 접시 테두리와 뚜껑 유성펜 글씨에 고착돼 콜로니를 체계적으로 피한다.

`349.jpg`는 2,800개를 검출하고 정답 99개 중 **0개**를 맞혔다. 어노테이션을 그려 보면
빨간 원이 뚜껑 글씨 "EXP: 2019/03/07…"의 획을 따라 그려져 있다.

### 4.2 근본 원인

파이프라인 전체가 fixture 한 장(`tests/fixtures/agar_sample.jpg`, 1350×910, 4×2 웰
플레이트)의 촬영 조건에 **절대 픽셀로 고정**되어 있다.

| 항목 | fixture | `sample/` |
|---|---|---|
| 용기 | 4×2 사각 웰 플레이트 | 원형 페트리 접시 |
| 해상도 | 1350×910 | 2048~4000px |
| 콜로니 반경 | 3~5px | 28~116px (**약 20배**) |
| 명암 극성 | 밝은 배경 / 어두운 콜로니 | **이미지마다 섞여 있음** |
| 방해 요소 | 격자 벽 | 테두리 링, 뚜껑 글씨, 금속 받침 |

깨지는 가정 5개:

1. **`WELL_ROWS=2, WELL_COLS=4`** ([config.py:30-31](../../app/config.py#L30-L31)) —
   `_well_mask`가 이미지를 4×2 격자로 자른다. 원형 접시엔 무의미. 어두운 배경에서는
   `_plate_roi`의 Otsu가 "밝은 plate"로 금속 받침 링을 골라 ROI가 엉뚱해진다.
2. **`DEFAULT_TOPHAT_KERNEL=31`** ([config.py:7](../../app/config.py#L7)) — 주석에
   "콜로니보다 크게"라고 적혀 있으나 이 콜로니는 지름 56~232px다. 커널이 작아서
   콜로니 몸통이 아니라 **표면 질감**에만 반응한다.
3. **`DEFAULT_INVERT=True`** ([config.py:6](../../app/config.py#L6)) — "콜로니가 배경보다
   어둡다"를 가정. 실측하면 그룹과 무관하게 섞여 있다 (bright 9장 중 8장은 어두운 콜로니,
   lower-res 10장 전부 밝은 콜로니, vague는 4:6). **그룹명으로 극성을 추정할 수 없다.**
4. **`WATERSHED_MIN_DISTANCE=5`** ([config.py:37](../../app/config.py#L37)) — 반경 100px
   콜로니를 산산조각 낸다. `13895.jpg`는 연결성분 174개 → 검출 886개로 **5배 증폭**.
5. **면적·반경 상한이 절대 픽셀** — `min_area=6`, `max_area=5000`, `PICK_RADIUS_MAX=20`.

### 4.3 슬라이더로 못 고친다 — 시도한 것들

0~100 슬라이더는 `threshold_offset`/`min_area`/`max_area`/`edge_margin`만 움직여서
원인 1~4번 중 아무것도 건드리지 못한다. 12가지 조합을 시도했고 전부 실패했다.

| 이미지 | 설정 | 검출 | 실제 맞힘 |
|---|---|---:|---:|
| 13895 (정답 19) | `min_size=80` | 19 | 개수만 일치, 위치는 전부 테두리 |
| 13895 (정답 19) | `mask_walls=off, tophat=189, 면적스케일` | 21 | **0개** |
| 349 (정답 99) | `mask_walls=off, invert=off, tophat=91` | 70 | **0개** |

정답 라벨에서 콜로니 크기·극성을 읽어 커널과 면적을 맞춰주는(실전에선 불가능한 치트)
경우까지 시도했으나 재현율이 4% 아래로 무너졌다.

### 4.4 보류된 위험 — 해상도 민감도

**사용자 지시로 이번 범위에서 제외.** 다만 목표 도메인에도 그대로 적용되는 위험이다.

같은 fixture(웰플레이트)를 배율만 바꿔 넣으면:

| 배율 | 해상도 | 검출 |
|---:|---|---:|
| 0.50 | 675×455 | 78 |
| **1.00** | **1350×910** | **635** |
| 2.00 | 2700×1820 | 1,662 |
| 3.00 | 4050×2730 | 20,305 |

실제 촬영 장비 해상도가 1350×910으로 확정되면 문제없다. 다르거나 가변이면 이 항목을
다시 열어야 한다.

## 5. 다음에 할 일 — 승인된 설계

**설계서: [specs/2026-07-28-plate-strategy-design.md](specs/2026-07-28-plate-strategy-design.md)**
사용자 승인 완료. **구현 시작 안 함. 구현 플랜(writing-plans)도 아직 없음.**

### 5.1 결정된 범위

| 항목 | 결정 |
|---|---|
| 운영 대상 | **4×2 웰 플레이트.** 페트리는 다른 제품라인/향후 과제 |
| 용기 판별 | 요청 파라미터 `plate_type` (런타임 자동 판별 안 함) |
| 페트리 범위 | 구조 seam + best-effort. **정확도 목표 없음** |
| well8 구현 | **코드 이동만, 로직 무변경** |
| 해상도 정규화 | 제외 |
| 평가 게이트 | 걸지 않음 (측정 수단만 확보) |

### 5.2 구현할 것

```
app/plates/
  __init__.py   — get_plate(name) 레지스트리
  base.py       — PlateStrategy 프로토콜 (roi, default_invert)
  well8.py      — 기존 _plate_roi / _well_mask 를 로직 변경 없이 이동
  petri.py      — 원형 ROI (scripts/petri_roi_prototype.py 를 옮김)
```

API 변경:
```python
plate_type: Literal["well_8", "petri"] = "well_8"
invert: bool | None = None      # None = 전략이 결정
```

`invert` 타입 변경이 유일한 기존 필드 수정이다. 미지정 시 `well8`이
`config.DEFAULT_INVERT`(True)를 돌려주므로 **기존 동작과 동일**하다.

`pick_region()`도 전략 ROI를 쓰도록 바꿔야 한다 (현재 `_well_mask` 직접 호출).

### 5.3 페트리 예상 성능 — 실측

프로토타입 ROI를 39장에 적용한 결과 (기준선 `mask_walls: false`):

| 지표 | ROI 없음 | ROI 적용 |
|---|---:|---:|
| 검출 | 150,738 | 100,509 |
| 정밀도 | 0.55% | **0.82%** |
| 재현율 | 44.1% | 43.6% |

정밀도 1.5배, 재현율 유지. **그래도 1% 미만이다.** 지배적 오검출원(뚜껑 글씨, 표면 질감,
watershed 과분할)이 접시 **안**에 있어 ROI로 안 걸러진다.

**이 작업 후에도 페트리는 실사용 정확도가 되지 않는다.** 합의된 범위와 일치하며 설계서
§3.4.1에 명시돼 있다. 기대치를 여기서 못박아 둔다.

### 5.4 성공 판정

정확도 수치가 아니라 셋:

1. 기존 74개 테스트 **무수정** 통과 (웰플레이트 무회귀)
2. `plate_type: "petri"` 적용 시 정밀도가 기준선보다 오르고 재현율이 안 떨어짐
3. `scripts/evaluate_labeled.py` 한 줄로 정확도 측정 가능

추가로: `plate_type` 미지정 == `"well_8"` == 현재 출력이 **콜로니 리스트 전체 일치**
(개수만이 아니라 `colonies` 배열 equality).

## 6. 최우선 과제 — 설계보다 먼저

### 6-1. 웰 플레이트 촬영본 확보와 라벨링 🔴

**최종 목표는 검출률 향상인데, 목표 도메인의 정확도를 잴 수단이 아예 없다.**

- 리포 내 웰플레이트 이미지: `tests/fixtures/agar_sample.jpg` **1장, 라벨 없음**
  (`output/` 의 나머지는 생성된 진단·더미 파일)
- 기존 74개 테스트는 "감도 올리면 검출 수가 는다" 같은 **방향성만** 검증한다.
  정확도를 재는 테스트는 하나도 없다.
- 즉 지금 무엇을 개선해도 좋아졌는지 알 수 없다. §5 설계도 페트리만 측정 가능하다.

**필요한 것:** 실제 장비로 촬영한 웰플레이트 이미지 + `sample/`과 같은 형식의 라벨.

```json
{"colonies_number": 19,
 "labels": [{"class": "...", "x": 300, "y": 915, "width": 244, "height": 244}]}
```
`x`, `y` 는 박스 **좌상단** (시각 확인 완료). 라벨이 생기면 아래 명령 한 줄로 측정된다.

몇 장·콜로니 몇 개가 필요한지는 사용자와 상의가 필요하다.

### 6-2. 그 외 후속

1. 해상도 정규화 (§4.4)
2. 뚜껑 글씨·기재 사항 제거 — 페트리 정밀도의 실질 병목
3. watershed 재설계 (콜로니 크기 비례 씨앗 간격)
4. 라벨 1,886개를 활용한 학습 기반 검출 검토

## 7. 재현 도구

세션 임시 폴더에 있던 조사 스크립트를 리포로 정리해 넣었다. **`vision/` 에서 실행한다.**

### 정확도 측정

```
.venv\Scripts\python scripts/evaluate_labeled.py sample
.venv\Scripts\python scripts/evaluate_labeled.py sample --json out/eval.json
.venv\Scripts\python scripts/evaluate_labeled.py sample --param min_size=80
.venv\Scripts\python scripts/evaluate_labeled.py sample --param plate_type=petri
```

[scripts/evaluate_labeled.py](../../scripts/evaluate_labeled.py) — 검출 중심이 정답 박스
안이면 TP(탐욕적 1:1). 이미지별·전체 정밀도/재현율과 **무작위 산포 기준선**을 함께 낸다.
기준선보다 낮으면 검출기가 정답을 피하고 있다는 신호다.

40장 전체는 약 2분 걸린다. 빠른 확인은 `sample/lower-resolution` (10장, 약 10초).

### 페트리 ROI 프로토타입

```
.venv\Scripts\python scripts/petri_roi_prototype.py sample
.venv\Scripts\python scripts/petri_roi_prototype.py sample --dump output/roi
```

[scripts/petri_roi_prototype.py](../../scripts/petri_roi_prototype.py) — `app/plates/petri.py`
로 옮길 로직의 검증본. `--dump`는 ROI를 그린 확인용 이미지를 저장한다.

실측: 접시 검출 32/40, 배경 41~64% 제거, 극성 추정 30/39.

### 어노테이션 이미지 확인

기능은 **이미 있다.** [api.py:139-147](../../app/api.py#L139-L147)의
`POST /detect/preview`가 콜로니를 그린 이미지를 base64 PNG로 반환하고, `/detect`는
`save_annotated: true`로 `output/`에 저장 후 경로를 준다.

알려진 한계: `/detect/preview`는 `count`와 `image`만 돌려줘서 좌표까지 필요하면 두 번
호출해야 한다(고해상도는 회당 3~5초). 정확도가 정리된 뒤에 손대는 게 맞다.

**정확도를 볼 때는 반드시 어노테이션을 그려서 위치를 확인할 것.** §3, §4.3에서 보듯
개수만 보면 완전히 틀린 결론에 도달한다.

## 8. 사용자가 밝힌 의도

- **최종 목표는 콜로니 검출률·정확도 향상.** "비전서버니까."
- `sample/`은 실제 웰플레이트 촬영 전에 가져온 **대역 데이터**. 목표 도메인 아님.
- 운영 대상은 웰 플레이트이되 **두 용기 모두 지원**하고 싶음 (→ `plate_type` 설계).
- 해상도 변동 문제는 **지금은 제외**.
- 웰플레이트 가정을 코드에 못 박지 말 것.
